How offline mode works

  1. Open this page while online. The service worker caches only this generic capture screen and its static assets so the page can reopen without a connection.
  2. Unlock with your passphrase. The browser derives an encryption key with PBKDF2 and encrypts each text-only draft using AES-GCM before saving it in IndexedDB. The passphrase is never stored.
  3. Capture text while disconnected. Drafts stay on this device. No AI/Gemini call is made, and voice recordings, report files, and AI results are not cached or queued.
  4. Reconnect and sign in. Press Sync (or allow the online reconnect handler) to send drafts through the authenticated sync API. A unique client ID prevents duplicate cases; a draft is marked synced only after server confirmation. Unconfirmed drafts remain local.

Why no offline voice? Browser speech recognition is not consistently available offline and may send audio to a browser/provider service. To avoid implying private or reliable offline transcription, this queue intentionally supports text only. Use voice only in the separate online workflow after checking consent and connection status.

What this offline queue does — and does not do

✓ Encrypted locally

AES-GCM with a key derived from your passphrase using PBKDF2. The passphrase is not stored.

✓ Idempotent server sync

The server uses a unique client ID to prevent duplicate cases if sync is repeated.

✓ Manual-review state

Synced cases are labelled offline sync; no AI output is fabricated while disconnected.

✕ No media in offline queue

Reports and raw audio are not stored or uploaded by this screen. Use the separate report workflow online.
